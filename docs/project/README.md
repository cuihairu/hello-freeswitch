# 第 13 章 · 智能客服项目概述

从这里开始进入实战项目篇。本篇以一个**电话智能客服系统**为目标项目，把前面各篇的知识——Sofia 接入、拨号计划、IVR、脚本、ESL——串成一个能落地的系统：来电自动应答，客户说出诉求，系统识别语音、理解意图，能答的直接答，不能答的转人工坐席，全程录音归档。

本章先回答三个问题：系统要做什么（需求分析）、各部分用什么技术（技术选型）、整体怎么拼起来（架构设计）。

## 需求分析

### 核心业务流程

一通典型来电的完整旅程：

1. 客户拨打客服号码，经运营商中继进入 FreeSWITCH；
2. 播放欢迎语与 IVR 菜单，客户可以按键，也可以直接说话；
3. 说话内容被转写成文本（ASR），再交给 NLP 判定意图；
4. 常见问题由机器人直接播报答案（TTS 或预合成提示音）；
5. 识别不了、情绪激动或客户主动要求时，转接人工坐席；
6. 通话全程录音，挂断后录音与通话记录归档，供质检与回溯。

### 功能需求拆解

| 能力 | 需求要点 | 主要承载 |
| ---- | ---- | ---- |
| 来电接入 | 中继对接运营商、号码接入、主叫识别、黑白名单、时段路由 | FreeSWITCH（mod_sofia + 拨号计划） |
| IVR 导航 | 多级菜单、按键收集、超时/输错重试、工作时间分流 | FreeSWITCH（mod_dptools 的 `ivr` application / Lua 脚本） |
| 语音转写（ASR） | 实时流式识别为主，录音文件后识别为兜底；中文识别准确率达标 | 语音服务 + 媒体抓流模块 |
| 意图识别 | 判定客户意图、抽取实体（时间/号码/业务类型）、多轮澄清 | NLP 服务（云服务或自建） |
| 应答播报 | 机器人答案播报，支持动态文本（如话费金额） | TTS 服务 + FreeSWITCH 播放 |
| 坐席转接 | 排队、分配、未接 fallback、坐席与机器人通话之间的衔接 | FreeSWITCH（bridge/排队）+ 业务后端 |
| 录音归档 | 全程录音、按通话 UUID 命名、挂断后上传与索引 | FreeSWITCH 录音 + 业务后端 |

### 非功能需求

- **时延**：机器人应答的"听-想-说"往返要控制在秒级，超过两秒客户就会觉得"卡住了"；
- **并发**：按坐席规模与话务峰值估算并发通话数，FreeSWITCH 单节点数百路并发是常规量级，瓶颈通常在 ASR 服务而非交换；
- **可用性**：语音服务故障时要有降级路径（退回纯按键 IVR），不能"识别挂了电话就打不通"；
- **合规**：录音要播报提示（"通话将被录音"）、保存期限与访问权限要明确。

## 技术选型

| 层 | 选型 | 理由 |
| ---- | ---- | ---- |
| 呼叫接入与媒体 | FreeSWITCH | 开源软交换里生态最完整的一档：SIP/WebRTC 接入、拨号计划、IVR、录音、会议、转接全部内置；Linux 上稳定运行，单机并发能力强 |
| 控制通道 | ESL（Event Socket） | 事件上行 + 命令下行的标准通道，业务后端用它观测每一次呼叫并随时干预（见 [事件系统与 ESL](/advanced/events)） |
| 脚本层 | Lua（mod_lua） | 进程内执行、延迟极低，适合 IVR 菜单、按键收集这类"每通电话都要跑"的逻辑 |
| ASR / TTS | 独立语音服务 | 云厂商 API 或自托管引擎，与交换层解耦，可独立扩容与更换 |
| NLP | Dialogflow / Rasa / 自建规则 | 意图识别与多轮对话管理；三者可并存，规则作兜底 |
| 业务后端 | Python / Go / Java | 会话状态机、坐席调度、工单与 CRM 对接、录音归档 |

三条选型原则值得强调：

- **交换与智能分离**。FreeSWITCH 只负责"接得住、播得出、录得下、转得动"，所有语义理解都放在外部服务。语音与 NLP 技术迭代快，解耦之后换厂商不动交换层。
- **控制面走 ESL，媒体面走媒体流**。业务决策依赖事件（来话、应答、挂断、录音完成），干预依赖命令（应答、播放、转接、挂断），两条通道职责清晰，不互相污染。
- **任何智能环节都要有降级**。ASR 挂了退按键菜单，NLP 挂了播静态提示，TTS 挂了退预合成文件。客服系统是企业的入口线路，不能因为一个第三方接口整体不可用。

## 整体架构

```
          PSTN / 运营商中继（手机、固话来电）
                         |
                         v
+-- FreeSWITCH 节点 --- 呼叫接入与媒体处理 --------------------
|   mod_sofia 接入 · 拨号计划/IVR · 录音 · 转接 · RTP 媒体
+------+------------------------------------------+----------+
       |                                          |
       | ESL 控制通道（TCP 8021）                   | 媒体抓流（media bug）
       | 事件上行 / 命令下行                        | L16 实时音频流
       v                                          v
+-- 智能客服业务后端 ----------------------------------------+
|   ESL 客户端 · 呼叫状态机 · 坐席调度 · 录音归档 · 质检接口   |
+------+---------------------+---------------------+-------+
       |                     |                     |
       v                     v                     v
  ASR / TTS 服务         NLP 服务              业务系统
  流式识别 / 合成     Dialogflow / Rasa /     工单 / CRM / 数据库
                     规则兜底                       |
                                                  v
                                            人工坐席分机
                                            （注册在 FreeSWITCH 上）
```

数据流逐条说明：

1. **呼叫接入**：运营商中继 INVITE 进入 FreeSWITCH（通常对接在 external profile 或独立中继 profile），命中拨号计划里的客服入口，转给 Lua IVR 脚本或 ESL 后端接管；
2. **媒体流出**：需要识别时，在通话通道上挂 media bug 抓取音频，推给 ASR 服务（第 14 章详述）；若采用"逐句识别"，则直接 `record` 录音后把文件交给 ASR；
3. **事件上行**：FreeSWITCH 通过 ESL 把通道事件（来话、应答、录音开始/结束、挂断）推给业务后端，后端据此推进状态机；
4. **意图判定**：ASR 产出的文本交给 NLP 服务，得到意图与实体；
5. **应答与转接**：答案文本交 TTS（或命中预合成文件），后端用 ESL 命令播放；需要人工时 `originate` 坐席分机并桥接；
6. **归档**：挂断事件触发录音上传、CDR 入库、通话与文本记录关联。
